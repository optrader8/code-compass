# Code Compass 기여 가이드

## 시작하기 전에

Code Compass에 기여해 주셔서 감사합니다! 이 프로젝트는 오픈소스 커뮤니티의 지원 없이는 존재할 수 없습니다. 이 가이드를 따라주시면 프로젝트에 기여하는 데 도움이 될 것입니다.

### 행동 강령

Code Compass는 모든 참여자가 환영받고 존중받는 환경을 조성하기 위해 노력하고 있습니다. 모든 기여자와 참여자는 [행동 강령](../CODE_OF_CONDUCT.md)을 준수해야 합니다.

## 기여 유형

Code Compass는 다양한 방식으로 기여할 수 있습니다:

### 1. 코드 기여
- 버그 수정
- 새로운 기능 추가
- 성능 개선
- 테스트 추가

### 2. 문서 기여
- 사용자 문서 개선
- 설치 가이드 작성
- 예제 추가
- 번역

### 3. 문제 보고
- 버그 보고
- 기능 요청
- 사용성 개선 제안

### 4. 커뮤니티 지원
- 다른 사용자의 질문에 답변
- 코드 리뷰
- 프로젝트 홍보

## 설정 및 개발 환경

### 개발 환경 설정

1. **저장소 포크 및 클론**
   ```bash
   # GitHub에서 저장소 포크 후
   git clone https://github.com/your-username/code-compass.git
   cd code-compass
   ```

2. **의존성 설치**
   ```bash
   npm install
   ```

3. **개발 서버 시작 (옵션)**
   ```bash
   npm run dev  # 코드 변경 시 자동 재빌드
   ```

4. **빌드 확인**
   ```bash
   npm run build
   ```

5. **테스트 실행**
   ```bash
   npm test
   # 또는
   npm run test:watch  # 변경 시 자동 테스트
   ```

## 개발 프로세스

### 1. 이슈 찾기

- GitHub Issues에서 [good first issue](https://github.com/optrader/code-compass/labels/good%20first%20issue) 라벨을 확인하세요
- [help wanted](https://github.com/optrader/code-compass/labels/help%20wanted) 라벨을 확인하세요
- 자신이 해결하고 싶은 이슈를 찾고, 댓글로 작업 의사를 밝히세요

### 2. 브랜치 생성

```bash
# 메인 브랜치 최신 상태로 업데이트
git checkout main
git pull origin main

# 새로운 기능 브랜치 생성
git checkout -b feature/새로운-기능-이름
# 또는 버그 수정 브랜치
git checkout -b fix/버그-설명
```

### 3. 코딩 스타일

#### TypeScript 스타일 가이드
- 들여쓰기는 스페이스 2칸 사용
- 줄 길이는 80자 이내 유지 (가능한 경우)
- 변수명과 함수명은 camelCase 사용
- 상수는 UPPER_SNAKE_CASE 사용
- 인터페이스는 I로 시작하지 않음 (PascalCase 사용)

#### 예제 코드
```typescript
// 좋은 예
interface SearchOptions {
  caseSensitive?: boolean;
  regex?: boolean;
  contextLines?: number;
}

class CodeAnalyzer {
  private calculateComplexity(ast: ParsedAST): number {
    // 구현
    return 1;
  }
}

// 나쁜 예
interface iSearchOptions {  // 인터페이스는 I 접두사 사용 안 함
  CaseSensitive?: boolean;  // camelCase 사용
  regex?: boolean;
  context_lines?: number;   // camelCase 사용
}
```

#### 테스트 작성

- 모든 기능에는 적절한 테스트가 있어야 함
- 버그 수정 시 재발 방지를 위한 테스트 포함
- Jest를 사용한 유닛 테스트 및 통합 테스트 작성

### 4. 테스트 및 검증

```bash
# 모든 테스트 실행
npm test

# 코드 스타일 검사
npm run lint

# 타입 확인
npm run type-check

# 코드 커버리지 확인
npm run test:coverage
```

### 5. 커밋 메시지 작성

- 명령문 체를 사용 (예: "Add feature" not "Added feature")
- 제목 줄은 50자 이내로 제한
- 요약과 상세 설명은 빈 줄로 분리
- 변경 내용을 명확하게 설명

```bash
# 좋은 예
feat: 사용자 정의 검색 쿼리 기능 추가

CLI에서 사용자 정의 AST 쿼리를 실행할 수 있는
새로운 명령어를 추가했습니다.
```

```bash
# 나쁜 예
fixed some bug
```

### 6. 푸시 및 PR 생성

```bash
# 변경 사항 푸시
git add .
git commit -m "적절한 커밋 메시지"
git push origin feature/브랜치-이름
```

GitHub에서 Pull Request를 생성하고 다음 정보를 포함하세요:

- 변경 사항 요약
- 변경 이유
- 관련 이슈 번호 (있다면)
- 테스트 방법

## 코드 리뷰 프로세스

### 리뷰 기준

PR은 다음 기준을 충족해야 합니다:

- [ ] 모든 테스트 통과
- [ ] 코드 스타일 가이드 준수
- [ ] 적절한 테스트 포함
- [ ] 문서 업데이트 (필요 시)
- [ ] 성능 저하 없음
- [ ] 보안 취약점 없음

### 리뷰어 피드백 대응

- 피드백에 감사 인사
- 질문에 명확하게 답변
- 요청된 변경 사항을 적용하거나 대안 제시
- 변경 후 다시 리뷰 요청

## 기술 문서

### 아키텍처 설명

Code Compass는 다계층 아키텍처를 사용합니다:

- **CLI 계층**: 사용자 인터페이스와 명령 처리
- **코어 계층**: 비즈니스 로직과 워크플로우 조정
- **파서 계층**: 언어별 AST 파싱
- **유틸리티 계층**: 공통 기능 제공

### 주요 의존성

- `tree-sitter`: 고속 AST 파싱
- `@vscode/ripgrep`: 텍스트 검색
- `vscode-languageserver`: LSP 구현
- `commander`: CLI 인터페이스
- `jest`: 테스트 프레임워크
- `typescript`: 타입 안전성

## 자주 묻는 질문

### Q: 기여할 수 있는 쉬운 이슈를 어디서 찾을 수 있나요?
A: [good first issue](https://github.com/optrader/code-compass/labels/good%20first%20issue) 라벨이 붙은 이슈를 확인하세요.

### Q: 코드 스타일에 문제가 있나요?
A: `npm run lint` 명령어를 실행하여 스타일 문제를 확인할 수 있습니다.

### Q: 테스트 커버리지는 어느 정도가 되어야 하나요?
A: 새로운 기능은 최소 80% 커버리지를 목표로 해야 하며, 기존 코드는 90% 이상을 유지해야 합니다.

### Q: PR을 생성한 후 얼마나 걸려 리뷰가 오나요?
A: 보통 1-3 영업일 내에 리뷰를 제공하려고 노력합니다.
